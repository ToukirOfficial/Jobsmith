# Assumptions

Things the PRD and FEATURES list don't say, and what I decided. Change any of them by editing this file and `plan.md`.

## Accounts
- Setup is open only while the database has no users; creating the first user and closing setup happen in one transaction, so two visitors can't both claim it.
- The first user created by setup is a normal user. There is no admin role in V1 (no admin features are listed).
- Email codes: 6 digits, hashed, 10-minute expiry, 5 attempts, then a new code is needed. Asked at every login only when SMTP is set up (`MAIL_TRANSPORT=smtp`); `LOGIN_CODES=always|never` overrides.
- Cookie-based sessions use a double-submit CSRF token (`js_csrf` cookie + `X-CSRF-Token` header) and refuse requests from other origins.
- Access token lives 15 minutes, refresh token 30 days, rotated on every use; reuse of an old refresh token revokes the whole family.

## Jobs and applications
- A "job" and an "application" are the same record: a saved job is an application in the Saved stage.
- Companies are per user (each user's notes and contacts stay private); the sponsor register is shared, read-only data.
- Name normalisation: lower case, strip punctuation, `&` → `and`, drop suffixes (ltd, limited, plc, llp, inc, uk, group, holdings). Exact normalised match = sponsor badge; close matches (pg_trgm) are shown as "possible match" for the user to confirm.
- Duplicate warning: same normalised company + same normalised title, not archived. A warning, not a block.
- "Replied" in the funnel and response rates = the application reached Screening or later, or a received message was logged against it.
- Days in stage are counted from the last stage change.
- Salaries are stored as integer pence per year; hourly or daily rates are converted (37.5 hours / 5 days a week, 52 weeks) and marked as converted.

## Fetching and the bookmarklet
- The bookmarklet opens `/app/applications/new` in a new tab with the page URL, title and any selected text. On LinkedIn or Indeed pages, the server never fetches the URL; the user pastes or selects the job text.
- `robots.txt` is checked with the user agent `JobsmithBot`; if robots.txt can't be fetched, fetching is allowed (standard behaviour). Fetching runs in the queue; the browser polls the result.

## CV and documents
- Live preview uses the same templates as the final PDF, rendered in the browser; the saved PDF is always generated by the worker.
- Snapshots store both the full content (JSON) and the PDF file. A snapshot has no update or delete endpoint; it goes only when the whole application or account is deleted.
- Templates: "Classic" (Times), "Modern" and "Compact" (Helvetica), all single column, standard headings, no hyphenation. They use the PDF standard fonts, so no font files are shipped; the trade-off is that characters outside Western European (WinAnsi) text, such as some accented Eastern European letters, may not print correctly.
- A snapshot's PDF is rendered in the worker from the snapshot's own frozen content; attaching that PDF (setting its file once) is the only write a snapshot ever gets. "Mark as applied" can be recorded once per application.
- Generated "Download PDF" files are kept for 7 days; snapshot PDFs are kept as long as the application.

## Agent and AI
- Step 1 "Read the job" uses AI when a key is set; without one, it reuses the fields already extracted from JSON-LD or entered by hand.
- Step 4 "Pick the best CV version" is deterministic: the version with the highest keyword match score wins. With a key, the AI adds a one-paragraph explanation.
- Step 7 "Suggest a follow-up date" is deterministic: the user's follow-up days (default 7) from today or from the closing date, whichever is later, skipping weekends.
- Steps 2, 3, 4 and 7 never call AI. Steps 1, 5 and 6 need a key.
- Default models (overridable in settings or env): Gemini `gemini-2.5-flash`, OpenAI `gpt-5-mini`, Anthropic `claude-haiku-5-5`. Checked against each provider's current list before Phase 7.
- Monthly limit counts requests in the user's time zone's calendar month; when reached, AI steps stop with a clear message.
- One agent run per application at a time; a new run is refused while one is running.

## Visa salary rules
- `data/uk-salary-rules.json` holds Skilled Worker general and new-entrant thresholds with `effectiveFrom` dates and GOV.UK source links. The rule used is the one in force on the check date. Going-rate-per-occupation checks are not in V1 (they need SOC codes); the result says so.

## Reminders
- Reminders are rows with a unique key (e.g. `followup:<applicationId>:<appliedAt>`), so each fires once. The worker claims due rows atomically and stamps `sentAt`.
- "Interview tomorrow" fires at 09:00 the day before in the user's time zone; "closing soon" 3 days before the closing date.
- Without SMTP, reminders appear in-app only.

## Data
- Delete account needs the password and removes all rows and files immediately (no grace period).
- CSV import accepts up to 2,000 rows; unknown stages map to Saved.
- Export files are kept for 24 hours, then deleted by an hourly clean-up job. Exported CSV cells that start with = + - or @ get a leading apostrophe so spreadsheets don't run them as formulas.
- CSV import reads dates as ISO (2026-11-02) or UK order (02/11/2026). Salaries like "£48k" are read as yearly. A row without a job title or company is skipped and reported.
- Dashboard numbers are cached in Redis for 60 seconds and cleared after any change that affects them.

## Local seed login

- `pnpm db:seed` creates (or replaces) one fictional user: **demo@jobsmith.example / jobsmith-demo-2026** (Alex Morgan, a full-stack developer on a Graduate visa, eight weeks into a UK job search). Every company and person in it is made up and uses `.example` addresses. It only touches that one account and marks setup as done.

## Demo
- Demo data is generated by a seed script with obviously fictional names and companies (no real people). Recorded agent runs are JSON files in the repo, replayed with their original step timings.
- Demo key: stored against the demo session only, max 20 AI requests per session, deleted after 24 hours.
